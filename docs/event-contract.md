# عقد الأحداث الداخلي — `lansher-core`

> هذه الوثيقة مرجع تنفيذي: أي كود جديد يجب أن يطابقها. عند اختلاف الكود عن الوثيقة، تُحدَّث الوثيقة أولاً.

## 1. لماذا عقد واحد

كل مصدر أحداث (موصل TikTok، المحاكي، الاستيراد، أدوات الاختبار) يلتزم بهذا العقد. المحرك والطبقات والتكاملات لا تعرف المصدر، بل تعالج `LiveEvent` فقط. الفوائد:

- تبديل أو إصلاح موصل TikTok لا يمس القواعد ولا الواجهة.
- تصبح الاختبارات ممكنة بأحداث اصطناعية دون أي اتصال.
- إضافة منصة بث مستقبلاً (YouTube أو Kick) = موصل جديد فقط.

## 2. أنواع الأحداث

```rust
pub enum EventType {
    Chat,      // رسالة دردشة
    Gift,      // هدية (مع count و value_per_unit)
    Like,      // إعجابات (value = العدد)
    Follow,    // متابعة جديدة
    Share,     // مشاركة
    Join,      // دخول مشاهد
    Subscribe, // اشتراك أو عضوية إن وفّرها المصدر
    StreamStart,
    StreamEnd,
    Custom(String), // حدث مصدر خاص، تكتب له قواعد مخصّصة صراحةً
}
```

`Custom(String)` موجودة عمداً: بعض المصادر تضيف أنواعاً لا نعرفها مسبقاً، والقواعد تكتبها صراحةً بدل تجاهلها بصمت.

## 2.1 تمثيل JSON

الأنواع أعلاه ليست سلاسل نصية في JSON. `EventType` و`Payload` مُسلسَلان
بوسيط مُدمج `#[serde(tag = "kind", content = "...")]`، فالوحدة كائن لا نص:

```json
{ "event_type": { "kind": "Gift" } }
{ "event_type": { "kind": "Custom", "name": "horloge_tick" } }
{ "payload": { "kind": "Follow" } }
{ "payload": { "kind": "Gift", "data": { "name": "Rose", "count": 3, "value_per_unit": 5, "total_value": 15 } } }
```

المخطط الحاكم هو `schemas/event.schema.json`. أي اختلاف بينه وبين
`event.rs` أو `types.ts` نقص في العقد.

| النوع | الحقل الثاني | مثال |
|---|---|---|
| `EventType` | `name` للقيم غير الوحدة | `{"kind":"Custom","name":"x"}` |
| `Payload` | `data` لل قيم ذات بيانات | `{"kind":"Chat","data":{"text":"hi"}}` |

الأنواع عديمة البيانات (`Follow`, `Share`, `Join`) تُسلسل بلا حقل ثانٍ إطلاقاً.

## 3. شكل الحدث

```rust
pub struct LiveEvent {
    pub id: String,            // معرّف فريد من المصدر — أساس منع التكرار
    pub event_type: EventType,
    pub ts_ms: i64,            // وقت الحدث عند المنصة
    pub received_ms: i64,      // وقت وصوله للمحرك
    pub source: String,        // "tiktok" أو "sim" أو "import"
    pub user: Option<User>,
    pub payload: Payload,
    pub raw: Option<serde_json::Value>, // للتشخيص فقط، لا للقواعد
}

pub struct User {
    pub unique_id: Option<String>,      // معرّف دائم إن توفّر
    pub nickname: String,
    pub is_follower: Option<bool>,
    pub is_subscriber: Option<bool>,
    pub avatar: Option<String>,         // رابط أو مسار محلي
}

pub enum Payload {
    Chat { text: String },
    Gift {
        gift_id: Option<String>,
        name: String,
        count: i64,
        value_per_unit: i64,
        total_value: i64,
    },
    Like { count: i64 },
    Follow,
    Share,
    Join,
    Subscribe { tier: Option<String> },
    StreamStart { unique_id: String, title: Option<String> },
    StreamEnd { unique_id: String, duration_ms: i64 },
    Custom(serde_json::Map<String, serde_json::Value>),
}
```

### قواعد ثابتة في العقد

1. `id` إجباري وفريد. لا يُولَّد إلا مرة واحدة عند المصدر.
2. في الهدية: `value_per_unit` هو قيمة الهدية الواحدة، و`total_value = value_per_unit * count`. المحرك يحسب ولا يثق بقيمة محسوبة في المصدر.
3. `ts_ms` زمن الحدث عند المنصة، و`received_ms` زمن وصوله لدينا. الفرق بينهما يُستخدم لتشخيص التأخير.
4. `nickname` إجباري وقد يكون فارغاً. لا يُستخدم كمعرّف أبداً.
5. الحقول الاختيارية تحمل `None` إن لم يوفّرها المصدر. القواعد تعامل `None` كـ«غير معروف»، لا كـ `false`.
6. `raw` لا يُرسل للواجهة ولا للتكاملات الخارجية افتراضياً. للتشخيص فقط وبطلب صريح، لأنه قد يحتوي بيانات شخصية.
7. حمولة بلا حقول تُسلسل كوحدة: `{"kind":"Follow"}` بلا `data`. حمولة ذات حقول تتطلب `data`، إلا `Subscribe` وحقلها الوحيد `tier` اختياري بـ`#[serde(default)]`، فيقبل serde حذف `data` كاملاً: `{"kind":"Subscribe"}` و`{"kind":"Subscribe","data":{}}` و`{"kind":"Subscribe","data":{"tier":"level1"}}` كلها صالحة. من يقرأ الحمولة يجب أن يتعامل مع غياب `data` كـ`None` لا كخطأ.

## 4. منع التكرار

- نافذة منع تكرار: حلقة دائرية تحفظ `id` آخر 8192 حدثاً، مع حدّ زمني افتراضي 10 دقائق قابل للضبط من الإعدادات.
- يُطبَّق المنع **قبل** تشغيل القواعد، على مستوى المحرك لا على مستوى القاعدة، حتى لا تعالج قاعدتان نفس الحدث.
- بعض المصادر ترسل تاريخ الدردشة القديم عند فتح الغرفة. نعالج ذلك بمقارنة `ts_ms` بوقت فتح الجلسة مع هامش تسامح، إضافة إلى المقارنة بالمعرّف.
- تُعاد بناء الحلقة من السجل عند إعادة تشغيل التطبيق، حتى لا يتكرر حدث لمجرد إعادة التشغيل.

## 5. حالة المحرك

```rust
pub struct EngineState {
    pub running: bool,
    pub source_connected: bool,
    pub last_error: Option<String>,
    pub counts: Counts, // مشاهدون، إعجابات، هدايا، القيمة، عدد الجلسات
    pub session_started_ms: Option<i64>,
    pub unique_id: Option<String>,
    pub latency_ms: Option<i64>,
}
```

المحرك ينشر `EngineState` بعد كل حدث، والواجهة تعرضه. لا تستنتج الواجهة الحالة من الأحداث.

`running` يعني أن الجسر حيّ، فيضبطه `Bridge::new` عند الإقلاع. أما
`source_connected` فيعني وجود مصدر مرتبط. ربط مصدر جديد يبدأ جلسة بث
جديدة: `Engine::reset_session` يصفّر العدّادات ومنع التكرار ونتائج
الإجراءات، ويبقي القواعد كما هي.

`Counts` تحفظ `viewers` وحدها كحالة دورية يرسلها المصدر، وليست حدثاً؛
بقية الحقول أحداث جارية. لا تُشتق إحصاءات المحاكاة في الواجهة.

## 5.1 تقرير تمرير الحدث

`EngineReport` مُسلسل بمُوسِط `#[serde(tag = "result")]`، فيسافر مع كل
`push_event`:

```json
{ "result": "duplicate" }
{ "result": "no_match", "event_id": "e1" }
{ "result": "matched", "event_id": "e1", "rules": ["r1"] }
```

`rules` أسماء معرّفات القواعد التي ضربت، بعد نافذة منع التكرار ونافذة
المعدل. الواجهة تعرضها ولا تحسبها.

## 5.2 شكل الخطأ

```json
{ "ok": false, "request_id": "r7", "error": { "code": "unauthorized", "message": "رمز الدخول غير صالح أو منتهٍ" } }
```

`code` ثابت للاستهلاك الآلي ولا يُترجم. `message` عربية للعرض فقط، ولا
تُقارن نصاً في أي كود. الرد الناجح يحمل `data` ولا يحمل `error`، والعكس
للفشل. المخطط: `schemas/response.schema.json`.

## 5.3 مطابقة `Matches` (دلالة `*`)

`CompareOp::Matches` مقارنة نصية بنمط، ودلالتها محدّدة لا تخمين:

| النمط | النتيجة على `haystack` | السبب |
|---|---|---|
| `"rose"` | `rose` فقط | بلا `*` مطابقة كاملة، مربوطة الطرفين |
| `"*rose"` | `red rose` ✅ / `roses` ❌ | `*` الأولى فكّ ارتساء البداية |
| `"rose*"` | `roses` ✅ / `red rose` ❌ | `*` الأخيرة فكّ ارتساء النهاية |
| `"*rose*"` | `red roses` ✅ | ارتساء مفكوك من الجهتين |
| `"re*se"` | `red rose` ✅ | `*` وسط النمط تفصل مقاطع بالترتيب |
| `""` أو مسافة | لا يطابق أبداً | نمط فارغ لا يصلح شرطاً |
| `"*"` | يطابق أي نص غير فارغ | كل المقاطع فارغة، فالنمط بلا محتوى |

قواعد ثابتة:

1. `*` في الوسط **ليست** حرفاً حرفياً، بل فاصل مقاطع: `"re*se"` يطابق
   `red rose` لأن `re` يسبق `se`. لو قُصد حرفاً حرفياً فلا بد من
   شرط `Equals`.
2. المطابقة **غير حساسة لحالة الأحرف**، لأن `cmp_str` يطبّع النصّين قبل
   المقارنة.
3. النمط يُقصّ من الطرفين قبل الفحص، فـ`" rose "` و`"rose"` واحد.
4. التنفيذ في `lansher-core::rule::text_matches_pattern`، والنسخة
   المتطابقة في `UI/src/bridge.ts` للمحاكي. اختلاف بينهما يعني
   أن الواجهة تعرض نتيجة غير التي يقررها المحرك.

## 6. مسار الحدث داخل المحرك

```
مصدر → LiveEvent → منع التكرار → مطابقة القواعد (حسب الأولوية)
     → تحكم بالقاعدة (تبريد / تأخير / حد تكرار)
     → إجراءات متسلسلة (لكل إجراء مهلة)
     → ActionResult → سجل + نشر الحالة
```

فشل أي إجراء لا يوقف باقي القواعد ولا الإجراءات اللاحقة في نفس السلسلة. كل `ActionResult` يحمل نجاحاً أو خطأ مع رسالة، ويُسجَّل مع `rule_id` و `event_id`.

### 6.1 مدخل واحد للأحداث

كل حدث، أياً كان مصدره، يدخل عبر `Bridge::push_event`. لا يوجد مسار
بديل يمرّر الأحداث مباشرة إلى المحرك. هذا يجعل منع التكرار ونافذة
المعدل والإجراءات متطابقة بين الموصل الجانبي والمحاكي والاختبارات.

في جسر Tauri يُطلب ذلك بالرسالة `push_event`، وهي تمرّ بالمصادقة
كغيرها، وتردّ بـ `{ "report": EngineReport, "counts": Counts }`.

الواجهة لا تملك مُقيّم شروط كامل. `MockBridge` وحده يحمل مُقيّماً
مختصراً للمتصفح، وهو ناقص عمداً: الشروط التي تحتاج عدّادات أو نص
الحدث تُرجع «غير مطابقة» بدل تمرير قاعدة بالخطأ.

## 7. حواجز الأداء

- هدف: من استلام الحدث إلى تنفيذ أول إجراء أقل من 50ms في الحدث العادي.
- الإجراء البطيء (شبكة، صوت طويل، TTS) يُسلَّم إلى مشغّل تنفيذ منفصل بحد تزامن افتراضي 4، ولا يحجب مسار الأحداث.
- لكل قاعدة حد أعلى لمعدل التنفيذ. القاعدة التي تتجاوزه تُتخطى وتُسجَّل، ولا تُعطّل المحرك.

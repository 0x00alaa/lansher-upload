## الترتيب والموازاة

```
الموجة 1 (متوازية، لا تعارض بينها)
  W1 توثيق  ─┐
  W2 بحث    ─┼─ لا تمسّ عقد سطح المكتب إطلاقاً
  W3 سحابة  ─┘

الموجة 2 (وحدة واحدة)
  W4 المحرك ──► يملك العقد الرباعي حصرياً

الموجة 3 (تنتظر W4)
  W5 الواجهة ──► تستهلك أنواعاً جديدة، لا تكتب العقد

الموجة 4
  W6 فحص ودمج ──► البوابة النهائية
```

**ليش هالترتيب:** W1 وW2 وW3 لا تلمس عقد سطح المكتب، فتوازى بأمان.
W4 وحده لأنه يغيّر العقد في أربعة مواضع. W5 ينتظره لأنه يستهلك
أنواعه. W6 هو بوابة الدمج.

## قاعدة التصادم

نقطة التصادم الوحيدة هي **العقد الرباعي** (انظر `OWNERS.md`).
في أي موجة، **وكيل واحد فقط** يملكه. الباقي إما يعمل بمعزل عنه أو
ينتظره.

## التحقق الإلزامي قبل اعتماد أي مهمة

```powershell
cd G:\re\my-lansher
cargo test --workspace
cd apps\desktop
npm.cmd run build
```

`npm.cmd run build` يشغّل فحص العقد وفحص Rust البنيوي ثم
`tsc --noEmit`، فلا تمر أخطاء الأنواع ولا انحراف العقد.

## قبل أي أمر cargo

```powershell
cmd /c '"G:\Program\VC\Auxiliary\Build\vcvars64.bat" && set' |
  ForEach-Object { if ($_ -match '^([^=]+)=(.*)$') {
    [Environment]::SetEnvironmentVariable($matches[1], $matches[2], 'Process') } }
$env:Path = "$env:USERPROFILE\.cargo\bin;$env:Path"
```

السطر الثاني ليس اختيارياً: `vcvars64.bat` يضيف أدوات Visual Studio
فقط، فلولاه بقي `cargo` غير معروف بعد الحقن.
